## 共通原則（監査反映）

1. **Hierarchy は Content だけ**に付く。System／Interaction には付けない。
2. **Hierarchy は読む順番ではない。意味の段階である。**  
   字が小さくても H2 になりうる。大きくても H4 や System になりうる。
3. **親が Interaction でも、中のタイトル／説明文は Content** になりうる（カード内階層）。
4. **見た目・※印・クラス名では分類しない。** 文章の役割で判定する。
5. **生成ホームページ本文は対象外。**
6. コンテンツ連動アイコン（⚠ 等）は文字列と一体で、同じ Hierarchy に追従する（Ver0.1どおり）。

## H1

### 意味

**現在の主面を代表するタイトル。**

「画面のタイトル」一般ではなく、**ユーザーがいま操作している面**の代表名。

### 判定条件

- その面全体を一言で指しているか
- **同時に表示されても、ユーザーが操作している面だけが H1**（背面は一時停止）
- 原則、**アクティブな主面に H1 は1つ**

### 実例

| 状況 | 文言例 | 判定 |
|---|---|---|
| 入口フル画面 | ホームページをつくる | H1 |
| 個別編集 | キャッチ文 | H1 |
| 編集ハブ | 編集ハブ | H1 |
| モーダル開中 | 自分で作る | H1（背面の H1 は一時停止） |
| 注文の右ペイン代表名 | 注文画面 | その主面の代表なら H1 |

## H2

### 意味

**画面を意味ごとに区切る大きな見出し。**

「問い」はその代表例。問い以外の区切り見出しも含む。

### 判定条件

- 主面（H1）の**内側**で、大きな意味ブロックを分けているか
- 疑問形でなくてもよい（例: 基本情報）
- 単一フィールドの名前なら H3（H2 にしない）

### 実例

| 文言例 | 判定 | メモ |
|---|---|---|
| キャッチ写真に文字を載せますか？ | H2 | 問い |
| 基本情報 | H2 | 区切り（問いではない） |
| キャッチの文章はどれに… | H2 | 工程ブロックの見出し |
| どこを？ | H2 | 問い |
| 店名（必須） | H3 | 項目名 |

---

## H3

### 意味

**項目名。**  
何を入れるか／何についての欄・属性かの名前。

### 判定条件

- 入力・選択・属性の**名前**か
- 面全体の代表名（H1）でも、大きな区切り（H2）でもないか
- Selection Card／Toggle の**カード内タイトル**も H3 になりうる（親UIは Interaction）

### 実例

| 文言例 | 判定 |
|---|---|
| 店名／電話番号／タイトル | H3 |
| タイトルの大きさ／サブキャッチの行数 | H3 |
| 文字の下地（形）／下地の色 | H3 |
| 場所から編集（カードタイトル） | H3 |
| キャッチ文（画面全体の名） | H1（H3ではない） |

## H4

### 意味

**読む補足（対象辞典）。**  
項目・選択肢・対象について **「これは何？」** に答える説明。

- 操作手順書・いまの案内ではない
- **細い段**である（H1〜H3 と同じ頻度で使う必要はない。稀用でよい）

### 存在理由（一文）

> H4は、項目・選択肢・対象について「これは何？」に答える読む補足であり、操作・状態の案内（System）でも項目名（H3）でもない段である。

### 判定条件（H4 ↔ System・二段判定）

#### 第1判定（主）— 何を説明しているか

| 説明しているもの | 行き先 |
|---|---|
| **対象そのもの**（これは何？／項目・選択肢・素材の意味・特徴・仕様） | **H4候補** |
| **現在の操作・状態・制約・結果**（いま何をする／いまどうなっている） | **System** |

#### 第2判定（補助）— 迷ったときだけ

```text
「今」を抜いても、対象の説明として成立する？
  はい → H4寄り
  いいえ → System寄り
```

**「今」テストを主判定にしない。**

### 実例

| 文言例 | 判定 | 理由 |
|---|---|---|
| ページの場所を選ぶ（カード note） | H4 | 選択肢は何か（対象辞典） |
| 講師・士業・フリーランスなど | H4 | 選択肢の意味 |
| 『下の枠』＝キャッチ写真の下に並ぶ小さな枠です | H4 | 対象の定義 |
| 推奨の比率は横16：縦9…（対象の仕様説明として） | H4 | 対象そのもの |
| 20文字以内で**入力してください** | System | 現在の操作制約 |
| 0 / 24 | System | いまの到達量 |
| 次は色を選んでください | System | いまの手順 |
| 現在読み込み中です | System | いまの状態 |
| step-help／コーチ／gate-lead | System | Ver0.1裁定どおり |

### 細い段としての位置づけ

- H4 は **常用しない**
- 代表画面では 0件〜数件になりうる（検証済み）
- 「4段あるから4段使う」ではない

## カード内階層

```text
親UI … Interaction（Selection Card / Toggle）
 ├ タイトル … Content / H3
 └ 説明   … Content / H4（第1判定で「対象そのもの」の場合）
```

HTML でも普通にある構造。違和感なし（監査承認）。

## H4を残す判断（監査比較の記録）

| 案 | 内容 | 結論 |
|---|---|---|
| A. H4残す | 対象説明を H3／System に潰さない | **採用** |
| B. H4削除 | H1〜H3＋段なし本文 | 運用は可能だが、境界が濁りやすい |

削れるが、**残した方が境界がきれい**（監査評価済み）。
